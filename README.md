# Mini NPU Simulator (MAC 연산 기반 패턴 인식기)

외부 수치 연산 라이브러리(NumPy 등) 없이 순수 Python만을 사용하여 NPU(Neural Processing Unit)의 핵심 연산인 **MAC(Multiply-Accumulate)**을 구현한 콘솔 애플리케이션입니다. 입력 패턴과 필터 행렬 간의 유사도 점수를 계산하여 패턴(`Cross` / `X`)을 판정하고, 입력 크기($N \times N$)에 따른 연산 성능 및 시간 복잡도를 분석합니다.


## 1. 실행 방법
* **실행 환경:** Python 3.8 이상 (외부 라이브러리 없이 표준 라이브러리 `json`, `time`만 사용)
* **파일 위치:** `main.py`와 `data.json`이 동일한 디렉터리(`C:\python-study\calculator-11\`)에 위치해야 합니다.
* **실행 명령어:**
  ```bash
  python main.py
  ```
* **모드 선택 방법:**
  * `1` 입력: **사용자 입력 모드** — 3×3 필터 A, B와 3×3 입력 패턴을 한 줄씩(공백 구분) 입력하여 MAC 점수, 평균 연산 시간, 판정 결과를 확인합니다.
  * `2` 입력: **data.json 분석 모드** — `data.json`에서 5×5, 13×13, 25×25 필터 및 패턴을 일괄 로드하여 검증하고, 크기별 성능 표와 테스트 결과 요약을 출력합니다.

---

## 2. 구현 요약
* **MAC(Multiply-Accumulate) 연산 구현:**
  * NumPy 등 벡터화 라이브러리를 사용하지 않고, 이중 `for` 반복문을 통해 입력 행렬과 필터 행렬의 같은 위치 $(i, j)$ 원소를 곱한 뒤 누적합(`score += matrix_a[i][j] * matrix_b[i][j]`)을 계산하는 방식으로 직접 구현했습니다.
* **라벨 정규화(표준화) 방식:**
  * `data.json` 내부의 서로 다른 라벨 표기를 통일하기 위해 프로그램 내부 표준 라벨로 `Cross`와 `X`를 사용합니다.
  * `expected` 값의 `'+'` -> `Cross`, `'x'` -> `X`로 매핑하고, `filters` 키의 `'cross'` -> `Cross`, `'x'` -> `X`로 정규화하여 일관된 기준으로 비교 및 출력합니다.
* **부동소수점 및 동점 처리 정책 ($\epsilon$):**
  * 실수(float) 곱셈·덧셈 과정에서 발생할 수 있는 미세한 부동소수점 오차를 고려하여 허용오차 $\epsilon = 10^{-9}$ (`1e-9`) 기준을 적용했습니다.
  * 두 필터 점수의 차이 `abs(score_a - score_b) < 1e-9`인 경우 어느 한쪽으로 판정하지 않고 `UNDECIDED`(판정 불가)를 반환합니다.
* **스키마 및 입력 검증:**
  * 모드 1에서는 행·열 개수 불일치 및 숫자 변환(`float`) 오류 시 안내 문구를 출력하고 재입력을 유도합니다.
  * 모드 2에서는 패턴 키에서 추출한 크기 $N$과 실제 필터·패턴 행렬의 크기($N \times N$)가 일치하는지 검증하여, 불일치 시 프로그램이 비정상 종료되지 않고 해당 케이스만 `FAIL` 처리합니다.

## 3. 결과 리포트

### 3.1 테스트 실행 결과 요약 (`data.json`)
* **총 테스트:** 6개
* **통과 (PASS):** 3개 (`size_5_2`, `size_13_1`, `size_25_2`)
* **실패 (FAIL):** 3개 (`size_5_1`, `size_13_2`, `size_25_1`)

### 3.2 FAIL 케이스 원인 분석
실패한 3개 케이스(`size_5_1`, `size_13_2`, `size_25_1`)의 원인을 **데이터/스키마 문제**, **로직 문제**, **수치 비교 정책**으로 분리하여 진단한 결과는 다음과 같습니다.

1. **데이터/스키마 및 연산 로직 점검 (정상):**
   * 라벨 정규화(`+` -> `Cross`, `x` -> `X`)와 행렬 크기 검증을 모두 정상 통과했으며, MAC 연산 누적합 계산에도 오류가 없었습니다.
2. **수치 비교 정책(동점 규칙)에 의한 판정 불가 (`UNDECIDED`):**
   * **실패 케이스별 실제 점수 계산 결과:**
     * `size_5_1` (기댓값 `X`): `Cross` 필터는 중앙 1칸만 겹쳐 `0.9 × 1.0 = 0.90`, `X` 필터는 대각선 9칸이 겹쳐 `0.1 × 1.0 × 9 = 0.90`으로 두 점수가 동일합니다.
     * `size_13_2` (기댓값 `Cross`): `Cross` 필터는 십자 25칸이 겹쳐 `0.3 × 1.0 × 25 = 7.50`, `X` 필터는 중앙 1칸이 겹쳐 `7.5 × 1.0 = 7.50`으로 두 점수가 동일합니다.
     * `size_25_1` (기댓값 `X`): `Cross` 필터는 중앙 1칸이 겹쳐 `4.9 × 1.0 = 4.90`, `X` 필터는 대각선 49칸이 겹쳐 `0.1 × 1.0 × 49 = 4.90`으로 두 점수가 동일합니다.
   * **분석 결론:** 세 케이스 모두 코드 오류가 아니라, 두 필터의 MAC 점수가 정확히 같아지도록 설계된 경계 테스트 데이터입니다. 본 프로그램의 허용오차 비교 정책(`|score_a - score_b| < 1e-9`)이 정상 작동하여 `UNDECIDED`로 판정되었고, 기댓값(`Cross` 또는 `X`)과 일치하지 않으므로 최종 리포트에서 `FAIL`로 분류되었습니다.

### 3.3 성능 표 해석 및 시간 복잡도 $O(N^2)$ 근거
I/O(파일 읽기 및 콘솔 출력) 시간을 제외하고 순수 `calculate_mac()` 함수 호출 구간만 10회 반복 측정한 평균 실행 시간은 다음과 같습니다.

| 행렬 크기 ($N \times N$) | 연산 횟수 ($N^2$) | 기준 크기(5×5) 대비 연산량 배율 | 평균 연산 시간 (ms) |
| :---: | :---: | :---: | :---: |
| **3×3** | 9 | 0.36배 | 0.020 |
| **5×5** | 25 | 1.00배 | 0.028 |
| **13×13** | 169 | 6.76배 | 0.196 |
| **25×25** | 625 | 25.00배 | 0.691 |

* **$O(N^2)$ 시간 복잡도 근거:**
  * `calculate_mac()`은 가로 $N$, 세로 $N$ 크기의 2차원 배열 모든 원소를 한 번씩 방문하기 위해 `N`번 반복하는 바깥쪽 루프와 `N`번 반복하는 안쪽 루프(이중 반복문)로 구성되어 있습니다.
  * 따라서 입력 크기 $N$에 대해 총 곱셈-누산 연산 횟수는 정확히 $N \times N = N^2$번 수행됩니다.
  * 실측 데이터에서도 행렬의 한 변 길이 $N$이 `5`에서 `25`로 **5배** 커질 때, 연산 횟수는 $25$회에서 $625$회로 **$5^2 = 25$배** 증가하며, 평균 연산 시간 역시 `0.028 ms`에서 `0.691 ms`로 약 **24.7배**(비례 수준) 증가합니다. 이를 통해 알고리즘의 시간 복잡도가 $O(N^2)$임을 이론과 실측 결과 모두로 확인할 수 있습니다.
